# План проєкту: спрощений Windows voice changer на базі форку w-okada/voice-changer

> Статус: затверджений план, жовтень 2026. Цей файл — вихідна точка для харнесу проєкту.

## Ідея

Форк [w-okada/voice-changer](https://github.com/w-okada/voice-changer) використовується як ядро
спрощеного десктопного додатку для Windows з трьома функціями:

1. **Ріалтайм зміна голосу "всюди"** — коли увімкнено, голос з мікрофона конвертується обраною
   RVC-моделлю і подається у віртуальний мікрофон, який будь-який додаток (Discord, ігри, Zoom)
   використовує як вхід.
2. **Тренування RVC-моделі** з аудіофайлів користувача (окрема вкладка).
3. **Текст у мовлення (TTS)** голосом обраної моделі.

Формат: десктоп, "ближче до заліза". Один стандартний Windows-інсталятор, який ставить усе
необхідне — користувач не має морочитись із залежностями чи віртуальними середовищами.

## Що вже є в ядрі (кодова база v1, MIT)

- Python-сервер (`server/MMVCServerSIO.py`): uvicorn + REST API (`server/restapi/`) для
  конфігурації + Socket.IO (`server/sio/`) для стрімінгу аудіо.
- RVC-пайплайн інференсу (`server/voice_changer/RVC/`):
  аудіо → embedder (HuBERT/ContentVec) → pitch extractor (crepe/rmvpe) → inferencer (.pth або ONNX).
- **Server device mode** (`server/voice_changer/Local/ServerDevice.py`): мікрофон → RVC → вихідний
  пристрій напряму через `sounddevice`, без браузера. Це основа задачі 1 (мінімальна латентність).
- Слоти моделей (`ModelSlotManager`), конвертер pth→ONNX (`onnxExporter`).
- React/TypeScript веб-UI (`client/demo/`), роздається сервером як статика.
- Підтримка інших моделей (MMVC, so-vits-svc, DDSP-SVC, DiffusionSVC, Beatrice, LLVC, EasyVC) —
  **баласт для цього проєкту, підлягає видаленню**.

## Чого в ядрі НЕМАЄ

- Коду тренування RVC (тільки інференс). Тренування — з Applio або оригінального RVC WebUI.
- TTS.
- Скриптів пакування у Windows-інсталятор (бінарники v2 автор збирає поза цим репозиторієм).
- Віртуального аудіодрайвера — потрібен VB-Cable.

## Ключові рішення

| Питання | Рішення |
| --- | --- |
| Інсталятор | Повний офлайн ("великий") інсталятор: PyTorch/CUDA-рантайм усередині (~2–4 ГБ). Зв'язка PyInstaller + Inno Setup. |
| VB-Cable | Бажано бандлити прямо в інсталятор (менше ризиків безпеки для користувача — ніяких сторонніх завантажень). **Для цього потрібен письмовий дозвіл VB-Audio на редистрибуцію** (їхня ліцензія забороняє її навіть для некомерційного використання). Fallback: інсталятор скачує VB-Cable з офіційного сайту vb-audio.com і запускає його інсталятор. |
| Ліцензія ядра | MIT — обмежень немає, зберегти LICENSE з копірайтом Wataru Okada у дистрибутиві. |
| Режим аудіо | Server device mode за замовчуванням (не client/browser mode). |
| UI | Залишити React-фронт, загорнути у десктоп-вікно (pywebview або Tauri) замість браузера. |
| Формат моделей | Розглянути "тільки ONNX" як основний шлях: менший інсталятор, швидший CPU-інференс; конвертер pth→onnx уже є в ядрі. |

## Фази

### Фаза 1 — MVP: ріалтайм зміна голосу (почати звідси)

1. Форк: видалити все, крім RVC (MMVC, so-vits-svc, DDSP-SVC, DiffusionSVC, LLVC, EasyVC,
   Beatrice) разом з їхніми залежностями з `requirements.txt`.
2. Server device mode за замовчуванням; мікрофон → RVC → VB-Cable Input.
3. Мінімальний UI: вибір моделі (слоти), вибір вхідного пристрою, pitch, кнопка on/off.
   Загорнути в pywebview/Tauri.
4. Пакування: PyInstaller → Inno Setup. Інсталятор ставить додаток + ваги
   (hubert/contentvec, rmvpe/crepe) + VB-Cable (бандл за наявності дозволу, інакше —
   завантаження з офіційного сайту під час інсталяції).
5. Перевірка на чистому Windows: встановлення "в один клік", Discord бачить VB-Cable
   як мікрофон, голос конвертується.

### Фаза 2 — TTS

- Безкоштовний локальний TTS (Piper або Edge TTS) → результат проганяється через той самий
  RVC-пайплайн → аудіо голосом обраної моделі. Переважно обв'язка, мало ML-роботи.

### Фаза 3 — Тренування RVC

- Інтеграція тренувального пайплайна з Applio / RVC WebUI: препроцесинг датасету, витяг фіч,
  тренування.
- Ризик: реально потрібна NVIDIA GPU (на CPU — години/дні). Серйозно розглянути хмарне
  тренування (Colab / власний бекенд), а локально залишити тільки інференс.
- Свідомо НЕ закладати в архітектуру фази 1.

## Ризики та відкриті питання

- **VB-Cable редистрибуція**: написати лист VB-Audio за дозволом на бандлінг. До отримання
  дозволу — fallback через завантаження з офіційного сайту.
- **Старі залежності v1**: `requirements.txt` розрахований на старі torch/fairseq; на свіжому
  Python може не збиратись. Рішення — заморозити Python 3.10 + конкретні версії пакетів
  усередині PyInstaller-бандла. Перевірити збірку на цільовому Windows ДО початку великої
  розробки. (Досвід боротьби із залежностями на Linux — див. `Linux_instal_history.md`.)
- **Розмір інсталятора** (~2–4 ГБ з CUDA): прийнято свідомо. ONNX-only шлях може суттєво
  зменшити розмір — оцінити у фазі 1.
- **Кодова база v1 vs v2**: у репозиторії тільки v1; вихідників v2 немає, тож орієнтуємось
  на v1 і не чекаємо апстрім-оновлень.

## Перший крок

Підняти сервер з форку на цільовому Windows (або хоча б зібрати PyInstaller-бандл з урізаним
RVC-only набором залежностей) і переконатись, що server device mode працює з VB-Cable,
встановленим вручну. Це знімає головні технічні ризики до будь-якої роботи над UI.
